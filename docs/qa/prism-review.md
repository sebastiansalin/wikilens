# Prism independent UI/UX review

Reviewed 2026-11-13. **Not a 9/10 pass.**

I can see the actual inherited browser screenshots, not only their text descriptions. Evidence includes Prism's paper entry screen, Apple graph with an empty comparison inspector, and the same graph with real comparison results. I also inspected the current Prism component/CSS and shared comparison component. I did not run a browser myself and did not verify motion or performance.

## Two fixes to prioritize

1. **Compress the embedded comparison hierarchy.** The parent inspector already says Compare editions and the workspace already identifies Apple. Remove the repeated eyebrow, large subject heading and intro inside the embedded variant. Keep language selectors and the run action within roughly 120 px, then show every pair in three short rows. On a 720 px-tall desktop, the full comparison overview should be visible without scrolling. Keep detailed edition evidence below it or add an explicit full comparison view.
2. **Make the graph's visible state legible and internally consistent.** The screenshot's 49-visible versus 36-of-49 conflict is a real defect, confirmed by the current source. Label the outer count as loaded articles, or use the actual renderer count. Give the root circle an opaque surface beneath its accent tint so edges cannot strike through the subject label. Keep progressive display rather than returning to a dense all-node graph.
